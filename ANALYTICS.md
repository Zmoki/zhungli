# Analytics

Anonymous usage stats in PostHog: project «zhungli.zmoki.xyz» (720394, US cloud), dashboards [«boring stuff»](https://us.posthog.com/project/720394/dashboard/2333552) (standard app metrics) and [«first run»](https://us.posthog.com/project/720394/dashboard/2379017) (the first minutes of new people).

## How it works

- `track(event, props)` in `stats.js` queues events and flushes them 2 s after the last one (and when the app goes to background).
- The batch goes to `/ingest/batch`, a Cloudflare Pages Function (`functions/ingest/batch.js`). It adds `$geoip_country_code` from Cloudflare, sets `$geoip_disable` and forwards nothing that identifies the visitor: no IP, no user agent. «Discard client IP data» is on in PostHog.
- On localhost and `file:` events only go to `console.debug('[stats]', …)`.
- Bots don't count as devices. The app sends nothing from bots that run JS (Googlebot, Lighthouse, headless Chrome, `navigator.webdriver`), and the ingest function drops batches whose user agent matches the same pattern, so old cached versions stop counting too. Data before this release still has some.
- On by default with a one-time notice (opt-out); off when `S.settings.stats === false` (checkbox «Статистика» in settings or «Выключить» on the notice). «Начать с чистого листа» keeps it off.
- What is sent is explained to users in `privacy.html`. Keep it in sync when adding a new kind of data.
- No plant names, nicknames, notes or photos. Custom plants are sent as `custom`.

## Common properties

On every event:

| Property | Value |
| --- | --- |
| `distinct_id` | random UUID in `localStorage['zhungli.anon']`, one per device; its first 8 characters are shown in settings so a user can ask to delete their data |
| `$geoip_country_code` | country from Cloudflare, added by the proxy |
| `app_version` | `?v=` of the app scripts |
| `plants_total` | number of plants on the device |
| `standalone` | `true` when opened from the home screen |
| `in_telegram` | `true` when opened inside Telegram's own browser (detectable on Android, often not on iOS) |
| `mini_app` | `true` when opened as the Telegram mini app (`/tg`, @ZhungliPlantsBot) |
| `tg_version` | mini app: Telegram's Bot API version |
| `tg_platform` | mini app: Telegram's client (ios, macos, tdesktop…) |
| `$os` | parsed from the user agent |
| `$device_type` | parsed from the user agent |
| `$host` | page origin |
| `$current_url` | page path |
| `$lib` | `zhungli` |
| `$process_person_profile` | `false`, no person profiles |

## Plant props

Sent together by events that `use` the «plant» group.

| Property | Value |
| --- | --- |
| `catalog_id` | catalog id or `custom` (was `plant_kind`) |
| `medium` | a [`medium` value](#value-lists); the plant's medium now (was `plant_type`) |
| `watering` | a [`watering` value](#value-lists) |
| `generic` | a generic catalog card |

## Adding or changing an event

[`analytics/events.json`](analytics/events.json) is the tracking plan and the source of truth: every event, its props, types, values and history. The tables above, the old-name translation in `functions/ingest/batch.js` and the PostHog event descriptions are made from it.

1. Call `track('noun_verb', { … })`: snake_case, past tense, props free of personal text. One tap sends one event (`ui_clicked` aside). A feature's events share a prefix: `bath_day_*` is the app's «Банный день» (settings and the card on «Сегодня»), `bath_*` one plant's choice in its card.
2. Add or change the event in `events.json`. Reuse prop names and value lists that exist (`plant` props, `medium`, `catalog_id`…). A `text` prop needs `why` and a line in `privacy.html`.
3. Renamed an event or a prop? Keep the old name in `was`: the ingest function translates it for phones still on an old version. Gone? Set `removed` to the first version without it; don't delete it.
4. `node tools/events.js --write`, then `node tools/events.js` must report no problems.
5. After the PR is merged, update PostHog from `node tools/events.js --posthog` (descriptions, tags, hidden) and any insight that used the old name.
